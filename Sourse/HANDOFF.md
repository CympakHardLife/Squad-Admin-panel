# SquadAdmin — техническая документация проекта

English version: HANDOFF-EN.md

Документ для того, кто будет дорабатывать проект. Инструкция для пользователя — в `README-RU.md`,
контракт API — в `API.md` (единственный источник истины по эндпоинтам).

## Что это

Панель администрирования сервера игры Squad. Один файл `SquadAdmin.exe`: без установки,
без внешних зависимостей, без интернета. Запускается на той же Windows-машине, что и
Squad-сервер, поднимает веб-панель на `http://127.0.0.1:8080` и хранит данные рядом с
собой (`config.json` + `data.db`).

Проект начинался как просьба «собрать exe из исходников SQCP» (Vue+Node+MySQL), но по
уточнениям заказчика превратился в собственное приложение на Go. Исходники SQCP и SquadJS
использованы только как референс протокола RCON — регулярные выражения парсеров перенесены
оттуда один в один.

## Требования заказчика (зафиксированы)

- Запуск на той же машине, что и Squad-сервер (домашний хостинг, Windows).
- Без входа по логину/паролю: панель локальная, слушает `127.0.0.1`, доступ
  ограничивается на уровне ОС/сети (авторизация удалена в 1.0.1 — см. changelog).
- RCON-модерация, редактор конфигов, управление процессом сервера, разбор логов,
  локальная база игроков, автоматизация.
- Русский — исходный язык интерфейса; начиная с 1.0.6 доступен переключатель RU/EN.
- **Целевая платформа — только Windows.** Linux-сборка использовалась при разработке для
  функционального тестирования и в поставку не входит.

## Архитектура

- Go 1.25, только stdlib + `modernc.org/sqlite` (чистый Go, БЕЗ cgo — принципиально для
  кросс-сборки exe). Зависимость `golang.org/x/crypto/bcrypt` убрана вместе с
  авторизацией в 1.0.1.
- Веб-сервер на `net/http`, маршрутизация через `http.ServeMux` с шаблонами
  `МЕТОД /путь/{id}` (Go 1.22+).
- Фронтенд вшит через `embed` из `internal/web/static/`: чистый HTML/CSS/JS без фреймворков
  и CDN, SPA с hash-роутингом.
- Живые обновления — SSE `/api/events`.

## Ключевые технические решения (не менять без причины)

- **SQLite строго через `modernc.org/sqlite`**, `db.SetMaxOpenConns(1)`. Переход на
  `mattn/go-sqlite3` сломает кросс-сборку exe: там нужен cgo.
- **RCON**: END-пакет как маркер конца ответа; обход сломанного пустого пакета Squad
  (`size=10` → пропуск 21 байта) обязателен, без него клиент рассинхронизируется.
  Заявленный размер входящего пакета проверяется на диапазон
  (`14…maximumPacketSize`): битый/отрицательный размер рвёт соединение с
  переподключением вместо паники; `readLoop` дополнительно под `recover`.
- **Действия над игроками** предпочитают команды `...ById` с игровым ID из кэша онлайна и
  падают обратно на варианты по имени/SteamID, только если игрока нет в сети.
- **Тимкиллы** — best-effort: лог даёт имя жертвы и EOS убийцы, команды берутся из кэша RCON
  через интерфейс `logwatch.TeamResolver` (реализован в `main.go` поверх снапшота менеджера).
- **Входы и выходы** считаются диффом онлайна из RCON (`tracker` в `main.go`), а не из лога:
  так они работают даже без доступа к файлу лога. События join/leave из `logwatch`
  подавляются, пока RCON подключён, — иначе были бы дубли.
- **Пароли в настройках** маскируются как `********`; пустая строка или маска при
  сохранении означают «не менять».
- **Бэкапы конфигов** перед каждой записью, максимум 10 на файл.
- **Кросс-компиляция**: ни одного build-тега и ни одного `_windows.go`. Ветвление по ОС —
  только через `runtime.GOOS` в рантайме. Нельзя использовать `syscall.Kill`,
  `syscall.SysProcAttr{Setpgid}` — их нет в Windows.
- **`WriteTimeout: 0`** у HTTP-сервера — иначе рвётся поток SSE.
- **`SQUADADMIN_HOME`** — переменная окружения для переноса рабочей папки, нужна для тестов.

## Сборка релиза

```
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o SquadAdmin.exe .
```

Результат — около 11 МБ, x86-64, без внешних зависимостей.

## Тестирование

- `go test ./...` — юнит-тесты парсеров RCON, mock RCON-сервера, `confedit`, `store`
  и `procman`.
- `internal/rcon/mockserver_test.go` поднимает фейковый Squad-сервер на `net.Listener`
  и проверяет в том числе multipacket и обход сломанного пакета.
- `internal/rcon/framing_test.go` — регрессия критичного дефекта: отрицательный/слишком
  большой размер пакета отбраковывается без паники, соединение рвётся.
- `internal/procman/procman_test.go` — `windowsTaskkillArgs` (никогда не `/PID 0`) и
  отсутствие двойного запуска при конкурентных `Start()`.
- Функциональная проверка при разработке велась linux-бинарником с `SQUADADMIN_HOME`:
  проверки API на curl (баны, деградация 409, автоматизация, настройки, SSE) плюс
  прогон против мока RCON на Python. Эндпоинтов входа/смены пароля больше нет.
- Фронтенд прогонялся под самописной DOM-заглушкой в Node: рендер всех 12 разделов,
  деградация, обработка SSE-событий, проверка экранирования HTML в никах и чате.

## Что осталось за кадром

- **Живого Squad-сервера при разработке не было.** Парсеры перенесены из SquadJS/SQCP и
  проверены на фикстурах реального формата, но боевую проверку можно сделать только на
  настоящем сервере. Наиболее вероятное место расхождений — ключи JSON в `ShowServerInfo`:
  они меняются от версии к версии игры, разбор написан терпимо (отсутствующие ключи дают нули).
- **Windows не тестировался** — в контейнере разработки не было ни Windows, ни wine.
  Проверена только успешная кросс-сборка. Windows-специфичные места, которые стоит
  проверить первыми: `tasklist`/`taskkill` в `procman`, открытие браузера через
  `cmd /c start`, пути с обратными слэшами в `confedit`.
- Снятие бана на самом сервере (`AdminRemoveBanById`) не реализовано: панель не знает
  идентификатор бана на стороне сервера. Бан снимается в базе панели, для сервера
  предусмотрена выгрузка `Bans.cfg`.

## Интернационализация (i18n)

Начиная с версии 1.0.6 фронтенд поддерживает два языка интерфейса: русский (исходный) и
английский. Бэкенд (Go) не менялся — все тексты на проводе по-прежнему русские; переводит
только клиент.

### Архитектура

В начале `app.js` расположен i18n-слой, оформленный как IIFE. Он инициализируется до любого
прикладного кода и регистрирует в глобальном пространстве функцию `T` и несколько её
методов.

**Словарь.** Объект `EN` содержит около 500 записей вида `'русская строка': 'English text'`.
Ключи — это дословные русские строки, использованные в коде; русский остаётся исходным
языком и не требует отдельного словаря.

**`T(key)`** — основная функция перевода строк интерфейса. В режиме `ru` возвращает ключ
как есть (без поиска по словарю). В режиме `en` ищет точное совпадение в `EN`; если запись
не найдена — возвращает ключ как есть. Это обеспечивает безопасную деградацию: строка,
пропущенная в словаре, просто останется русской.

**`T.err(msg)`** — перевод сообщений об ошибках, приходящих с бэкенда. Сначала ищет точное
совпадение в `EN`. Затем пробует шаблон `строка N: текст` и переводит его рекурсивно
(`line N: <перевод текста>`). Если и это не совпало — перебирает известные префиксы вида
`«Не удалось …: »` (ключи `EN`, оканчивающиеся на пробел), переводит префикс и рекурсивно
переводит остаток. Префиксы сортируются по убыванию длины, чтобы более длинные побеждали.

**`T.msg(msg)`** — перевод сообщений, сгенерированных бэкендом (журнал, лог автоматизации,
SSE-уведомления, результаты процессов). Расширяет `T.err`: после точного совпадения применяет
шаблонные правила из массива `RULES` (регулярные выражения для параметризованных сообщений),
затем префиксы, затем перевод по кускам через «, ». Подробности — в подразделе
«Сообщения бэкенда» ниже.

**`T.dom(root)`** — перевод статической разметки `index.html` (топбар, боковое меню). Обходит
DOM-дерево `root` через `TreeWalker`, переводит текстовые узлы по точному совпадению
(с сохранением окружающих пробелов), а также атрибуты `title`, `placeholder` и `aria-label`
у всех элементов внутри `root`.

**`T.lang`** — текущий язык (`'ru'` или `'en'`), читается из `localStorage` (ключ `sa_lang`,
по умолчанию `'ru'`). **`T.set(l)`** — сохраняет выбор в `localStorage`; новый язык
применяется после `location.reload()`.

**Подключение к остальному коду.** Все русские строковые литералы в прикладной части `app.js`
обёрнуты в `T('…')` автоматическим трансформером — строки-ключи остались русскими. В
HTTP-клиенте `api()` поле `data.error` из ответа сервера прогоняется через `T.err()`.
В разделе «Консоль» описания args/desc команд, пришедшие с бэкенда, переводятся через `T()`
прямо в месте рендера.

**Инициализация.** `app.js` подключён в конце `<body>`, поэтому `T.dom(document.body)`
вызывается сразу при выполнении скрипта. Одновременно `document.documentElement.lang`
выставляется в `'ru'` или `'en'`.

**Точки переключения языка.** Кнопка `#lang-toggle` в топбаре (`index.html`); стиль кнопки
добавлен в `style.css` рядом со `#theme-toggle`. Второй путь — сегмент «Язык интерфейса» в
разделе Настройки → Оформление (`renderSettings` в `app.js`).

**Сообщения бэкенда.** Записи журнала действий и журнала автоматизации, серверные
уведомления (SSE тип `notice`), результаты операций процесса, итоги проверок настроек и
события игрового лога формируются на бэкенде по-русски и хранятся в базе данных как есть.
На клиенте их переводит `T.msg(msg)`: точное совпадение по словарю → шаблонные правила
(массив `RULES` в i18n-слое: регулярные выражения для параметризованных сообщений —
PID, имена правил в «кавычках», счётчики игроков, времена) → префиксы («Не удалось …: »)
→ перевод по кускам через разделитель «, » (для составных итогов проверки папки).
Незнакомое сообщение возвращается без изменений — безопасная деградация. Благодаря
переводу при отображении старые записи журнала тоже показываются по-английски, а база
остаётся канонично русской. Точки применения `T.msg` в `app.js`: журнал (details),
лог автоматизации (detail, lastResult), тост SSE-уведомлений, детали статуса процесса,
результаты start/stop/restart, тосты проверок RCON/папки, тексты событий в разделе
Логи → События и в живой ленте на Обзоре.

### Правило для новых строк

Когда в будущей доработке добавляется новая строка интерфейса:

1. Написать строку по-русски и обернуть в `T('…')`.
2. Добавить парную запись в словарь `EN` в начале `app.js`: `'русская строка': 'English text'`.

Если шаг 2 пропустить, строка в EN-режиме просто останется русской — это безопасная
деградация, не баг. Словарь намеренно хранится в одном месте (начало `app.js`), чтобы
его было легко пополнять без поиска по файлу.

## Изменения в 1.0.1

Исправление по итогам технического аудита 1.0.0.

- **Удалена авторизация (по требованию заказчика — локальный запуск).** Экран
  входа, смена пароля, сессии и кука `sa_session` убраны. Из бэкенда удалены
  эндпоинты `/api/auth/*` и `/api/account/password`, middleware `auth`,
  `ensureAdmin`, KV-ключи `admin_hash`/`must_change_password`/`last_login_at` и
  таблица `sessions`. `guard` оставлен сквозной обёрткой, чтобы не переписывать
  таблицу маршрутов. Зависимость `x/crypto/bcrypt` удалена из `go.mod`.
  Это же снимает находку аудита о хранении токена сессии открытым текстом —
  токенов больше нет.
- **Критично: паника при аномальном RCON-пакете** (`rcon.go`). В `nextPacket`
  добавлена проверка диапазона размера, в `readLoop` — `recover`; битый поток
  переподключается, процесс не падает.
- **Критично: двойной запуск сервера** (`procman.go`). Введён `opMu`, под которым
  проверка «уже запущен» и `cmd.Start()` атомарны — конкурентные `Start()`
  запускают ровно один процесс.
- **Критично: ложный «сервер остановлен» + `taskkill /PID 0`** (`procman.go`).
  При неизвестном PID остановка идёт по имени образа (`/IM`), результат
  проверяется по наличию процесса, при неудаче возвращается ошибка. Убрано
  слово «SIGKILL» из сообщений Windows; снят BOM в выводе `tasklist`.
- Прочие важные и мелкие замечания аудита в этот выпуск сознательно не входят —
  запланированы отдельно.

## Изменения в 1.0.2

Закрыты важные («ВАЖНО») замечания аудита 1.0.0. Два из десяти отпали вместе с
авторизацией в 1.0.1 (троттлинг логина и завершение сессий при смене пароля) —
их предмета больше не существует. Остальные восемь исправлены ниже.

- **Проверка происхождения запроса** (`web/server.go`). `Handler()` теперь
  возвращает `mux`, обёрнутый в `localOnly`: `Host` обязан быть loopback,
  `Origin` (если есть) — тоже, `Sec-Fetch-Site: cross-site` отклоняется.
  Коды ошибок: `host_not_allowed`, `origin_not_allowed`, `cross_site_denied`.
  Проверка стоит до маршрутизации, поэтому покрывает и статику, и SSE.
  Замечание аудита про CSRF/DNS-rebinding после удаления пароля стало
  единственным барьером, отсюда жёсткость: `bindAll` больше не даёт доступ
  с других машин (сокет слушает, но запросы отбраковываются).
- **Атомарная запись конфигов** (`confedit/confedit.go`). Добавлен
  `writeFileAtomic`: `os.CreateTemp` в той же папке → `Write` → `Sync` →
  `Chmod` → `Rename` с пятью повторами на случай антивирусной блокировки,
  плюс `defer` на удаление временного файла. `WriteFile` использует его вместо
  прямого `os.WriteFile`. Бэкап `.bak-<ts>` как и раньше снимается заранее.
- **Сохранение standalone-комментариев в `Admins.cfg`** (`confedit/confedit.go`).
  Добавлены `adminsLayout` и `parseAdminsLayout`: комментарии привязываются к
  следующей за ними записи (`byGroup` по имени группы в нижнем регистре,
  `byAdmin` по ID), при сборке возвращаются на место. Комментарии удалённых
  через панель записей не теряются — уходят в хвост файла.
- **Защита правил автоматизации от повторного входа** (`automation/automation.go`).
  Введён `running map[int64]bool` с `tryAcquire`/`release`; отметка ставится
  в `tick()` **до** запуска горутины. `Store.RuleSetState` и `RuleMarkRun`
  теперь возвращают `error`, вызовы обёрнуты в `saveState`, который жалуется
  в `Notice`. Для `restart_schedule` неудачное сохранение состояния **отменяет**
  рестарт: иначе следующий тик через 30 секунд перезапустил бы сервер повторно.
- **Ротация лога по содержимому** (`logwatch/logwatch.go`). Хранится отпечаток
  первых 512 байт (`headProbe`). Лог только дописывается, поэтому старый
  отпечаток обязан оставаться префиксом нового; если это не так — файл
  подменили, читаем с нуля. Выбран отпечаток, а не `os.SameFile`: на Windows
  идентификатор подгружается лениво по пути, и для уже подменённого файла
  результат непредсказуем. Заодно пропускается UTF-8 BOM.
- **Терпимый парсер `ListPlayers`** (`rcon/squad.go`). `EOS: (\w{32})` →
  `([^\s|]+)`, `steam:` стал необязательным, `Team ID` допускает `N/A`,
  минуты/секунды в «Since Disconnect» — любой длины. Нераспознанные строки,
  похожие на запись об игроке, идут в `UnparsedLogger` (по умолчанию `log`)
  с антиспамом: одна строка не чаще раза в 10 минут, карта чистится после 200.
- **Версионирование схемы БД** (`store/store.go`). `PRAGMA user_version` +
  список `migrations`, каждый шаг в транзакции. Базовая схема вынесена в
  `schemaV1`. База, созданная более новой версией панели, отклоняется с
  понятной ошибкой. Для будущих шагов есть идемпотентный `ensureColumn`
  (SQLite не умеет `ADD COLUMN IF NOT EXISTS`).
- **Один опрос RCON за раз** (`rcon/manager.go`). Флаг `polling` +
  `tryBeginPoll`/`endPoll` в начале `pollOnce`, поэтому `ForcePoll()` после
  бана/кика не смешивается с фоновым циклом. Заодно `LatencyMs` считается как
  round-trip одной команды `ListPlayers`, а не «время всего опроса / 5».

Не входит в 1.0.2 (остаётся из раздела «мелочи» аудита): жёсткая привязка
обхода «битого» пакета Squad к байтовому паттерну, `Cache-Control: no-cache`
для статики, экранирование `%`/`_` в `SanitizeQuery`, проверка
`SeedLayer`/`LiveLayer` в `ValidateRule`, возможная смена CRLF→LF при «сыром»
редактировании прочих `.cfg`, отсутствие транзакций в многошаговых операциях
`store`. Тестов у `automation`, `procman`, `logwatch`, `web`, `config`
по-прежнему нет.

## Изменения в 1.0.3

Закрыты оставшиеся мелочи аудита 1.0.0.

- **`Cache-Control: no-store`** (`web/server.go`). Статика отдаётся с `no-store`
  вместо `no-cache` — ответ не сохраняется ни в каком кэше.
- **Экранирование LIKE** (`store/store.go`). `SanitizeQuery` заменяет `\`, `%`, `_`
  escape-последовательностями; все три группы LIKE-запросов получили `ESCAPE '\'`.
  Поиск `%` или `_` больше не матчит всё подряд.
- **ValidateRule для сидинга** (`automation/automation.go`). При `switchLayer: true`
  проверяется заполненность `seedLayer` и `liveLayer` — ошибка при создании правила,
  а не тихий сбой при срабатывании.
- **Нормализация CRLF в конфигах** (`confedit/confedit.go`). `WriteFile` вызывает
  `normalizeCRLF`: одиночный `\n` → `\r\n`. Squad на Windows требует CRLF;
  браузеры при «сыром» редактировании присылают LF. Тест `confedit_test.go`
  обновлён: ожидаемое значение round-trip теперь `\r\n`.
- **Транзакции в многошаговых операциях** (`store/store.go`). `UpsertSeenPlayer`,
  `SessionStart`, `SessionEnd` обёрнуты в `sql.Tx`. При `SetMaxOpenConns(1)` нет
  реальной конкурентности, но явная транзакция гарантирует атомарность при
  возможном повышении лимита и ускоряет пакетные вставки снапшотов.
- **Сигнатура `doStopWindows`** (`procman/procman.go`). Убраны `cmd *exec.Cmd`
  и `cmdDead bool` — POSIX-объекты, неприменимые на Windows (бывшие `_ = cmd;
  _ = cmdDead`). Вызов обновлён: Windows ветка передаёт только `pid` и `graceSec`.
- **Документация паттерна «сломанного» пакета Squad** (`rcon/rcon.go`). Комментарий
  к `nextPacket` теперь содержит точную байтовую сигнатуру (ссылка на SquadJS) и
  инструкцию: при изменении формата после патча Squad — проверять именно этот блок.
